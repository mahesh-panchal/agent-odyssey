The Stream of Ideas

Ideas keep arriving mid-task: what about this, could we also try that. One stream floods the hopper, so the mill has side channels for them. You will learn which channel each idea belongs in, and then how to carry what is left across to the next visit.

  • Goal: you will triage each new thought during a task into the right place (do now, park, quick question, helper, branch, or later session), and know what undo can and cannot restore.
  • Before you start: When to Start Fresh. Commands here are Claude Code commands.
  • Time: about 15 minutes.

Real work does not arrive in a straight line. You start fixing a samplesheet parser and think: “should I switch the aligner? What if I tried a stricter QC threshold? I also want to explore that other idea.” Typed into one conversation, each of those fills the context with side tracks.

Accuracy and recall degrade as context grows, and the whole conversation is re-sent on every request, so a cluttered session tends to cost more per step. A session with three unrelated tasks re-reads all of them on every turn of the fourth. Ideas are welcome. The fix is to triage each one.

Terms used here

  • Context: everything the model can see when it writes its next reply.
  • Turn: one prompt from you plus the model’s reply.
  • Session: one saved conversation with the agent, tied to a project folder.
  • Subagent: a helper the main agent starts. It works in its own separate, clean context (it knows what you tell it) and sends back a summary, so its reading stays out of your conversation.
  • Conversation branch (/branch, which is separate from a git branch): a copy of the conversation from this point, so you can try something in the copy while the original stays as it was. /fork is a different command: it copies the conversation into a separate background session.
  • Git worktree: a second checkout of the same repository in another folder, so two sessions can edit files without overwriting each other.
  • Checkpoint: a snapshot Claude Code takes at each prompt you send, so you can roll back with /rewind.

The triage

For each new thought, ask in this order. The key question is step 2: do you want the answer or the work during this session? If not, park it. If you do, steps 3 to 6 are the ways to get it.

  1. Does it block the current task? Do it now, in this session.
  2. Do you not want the answer or the work this session? Park it: write one line in a file and carry on. Parked ideas leave through the “later session” exit: once the current task is done, pick from the file.
  3. You want it now: is it a quick question you do not need on record? Use /btw <question>. It sees the conversation so far, has no tool access (it cannot read files, run commands or look at --help) and adds nothing to the history. So it suits questions about this conversation. An answer about a tool’s flags or defaults comes from the model’s memory: verify it against --help or the docs.
  4. You want it now: is it exploration where you only need a summary? Ask for a subagent (the built-in Explore helper is a fast read-only searcher), or use /subtask <task>, which starts a background helper that inherits the whole conversation and returns its result here.
  5. You want it now: is it a competing approach you want to try for real? Use /branch [name] to copy the conversation (the original stays reachable via /resume), or start a second session in its own worktree with claude --worktree <name>.
  6. You want it now: is it a different task entirely? Finish the current one, commit your work, then /clear or start a new named session (claude -n <name>, or /rename <name> inside one).
New thought Where it goes Why
“The parser crashes on this sample ID” (it is the task) Do now It blocks you
“Maybe a stricter QC threshold would help” Parking-lot line You do not want the answer this session; no cost to the context
“Which sample did we exclude earlier?” /btw One answer from the conversation; no tools; stays out of the history
“Where is the aligner configured across the repo?” Explore subagent or /subtask Heavy reading stays out of your main context; you get a summary
“Try the other aligner and compare” /branch or claude --worktree <name> A real attempt that can fail without spoiling the main path
“Redo the plots for the other project” (you want to start it now) Commit, then /clear or a new named session Different task, different files, different context

What a worktree shares

A worktree session isolates file edits only.

  • claude --worktree <name> creates .claude/worktrees/<name>/ on a branch called worktree-<name>.
  • Worktrees share the repository’s .git, and auto memory is per repository, so all worktrees share it.
  • A fresh checkout does not contain gitignored files such as .env unless you list them in .worktreeinclude. Large data folders need worktree.symlinkDirectories or a setup step. Plan for that before you start a pipeline test in one.

/branch copies the conversation. Any background helpers still running keep reporting into the branch.

Checkpoints and /rewind

Every prompt you send is a checkpoint. /rewind (aliases /checkpoint, /undo; or press Esc twice on an empty prompt) lets you restore code and conversation, only the conversation, or only the code.

The limits matter to bioinformatics:

  • Files changed only through shell commands (Claude Code’s Bash tool) are not tracked.
  • Subagent edits are mostly not restored.
  • Edits outside the session are not tracked.

Checkpoints do not replace version control. A sed -i or a script that rewrites a results table is a Bash change, so commit before you explore.

A parking-lot file

Keep the file outside what the agent reads every session: a file imported into your instructions file costs context each time. Keep it in the repository if the team should see it, in a gitignored file if it is personal, or use an issue tracker for anything that outlives the week.

# IDEAS.md  (one line each: date | idea | why it matters | revisit when)
2026-11-16 | Add a --dry-run flag to the parser | Check a samplesheet without writing output | after parser fix is merged
2026-11-16 | Stricter QC threshold (Q30 not Q20) | Fewer false variants in low-depth samples | when the test cohort is ready
2026-11-16 | Per-sample coverage plot | Spot dropouts faster | before the next batch

Worked example: you are fixing a samplesheet parser that rejects sample IDs containing a dot.

  • “Does the pipeline require the dot at all?” blocks the fix, so do it now.
  • “Would a stricter QC threshold help?” becomes a line in IDEAS.md.
  • “Which sample did we exclude earlier?” is a /btw. For “what does --min-qual default to?”, /btw can only guess from memory, so check --help.
  • “Where else do we split sample IDs on dots?” is wide reading where only the list matters: send an Explore subagent.
  • “Let’s try the other aligner and compare.” is a real experiment you want now: commit the fix, then use /branch or a worktree session.
  • “I should also tidy the figures for the other project.” is a different task for after the parser is done: commit, then /clear or claude -n figures in a later session.

The main session ends with the parser fixed and a short, readable history.

Commands: /btw, /subtask, /branch, /fork, /rewind, /clear, /rename, /resume, claude -n <name>, claude --worktree <name> (or -w).

Plan mode (/plan, or Shift+Tab until the bar shows it) makes Claude read and propose without editing until you approve. Try it for a side idea you only want to think through.

Check OpenCode’s documentation for its side-question, branch and worktree features. Its terminal page lists /new (alias /clear) for a fresh session, /sessions to return to one, /compact, and /undo and /redo (these need a git repository). In any tool, local models included, keep a parking-lot file and commit before exploring.
