The Context Window

A great hopper above the mill holds everything an Astral can see at once. You watch yours work, quick and willing, while the grain piles up around it. Pour in too much and the oldest grain spills out unseen, and the Astral never knows what it lost. Learn what goes into the hopper and how to keep it clean. Beyond this stop the road turns toward the Maze, where you learn to check what a creature tells you.

  • Goal: you will say what fills the context window, what happens when it is full, and three habits that keep it useful.
  • Before you start: Tokens, Not Letters, and an installed agent from Set Up Your Agent (on the OpenCode route, that includes Ollama and the model you pulled). A token is a chunk of text the model reads.
  • Time: about 20 minutes.

The context window is all the text the model can look at when it writes its next piece of output, including its own reply. It works like the model’s working memory and is separate from what the model learned in training. It is measured in tokens. It limits what an agent can keep in mind in a long task, so you need to know what fills it.

What fills it

In Claude Code (a coding agent that runs in your terminal), the window holds your instructions, the files it reads, its own responses, and content that never appears in your terminal. Before you type anything, it already holds:

  • the instructions file (CLAUDE.md, a text file loaded at session start by the harness, the program around the model that runs tools and sends your text)
  • auto memory (notes the harness keeps from earlier sessions)
  • the names of MCP tools (tools added from outside servers) and skill descriptions (short summaries of saved instruction sets)

Every file it reads and every tool output then adds more. With the API (programmatic access to the model) the same idea holds: the system prompt (the harness’s own instructions, sent with every request), every message, tool results, tool definitions and the output all count.

Sizes depend on the model, up to 1 million tokens for some and 200 thousand for others. A big window gives room for more text; quality depends on what fills it.

What the model stores while it writes

To write each new token, the model looks back at every earlier token in the window. Redoing that work for the whole window at every step would be slow, so the model keeps the results. For each earlier token it stores numbers computed from that token (called its keys and values) in a store named the KV cache (key-value cache). Each new token adds one entry, and the model reuses the rest.

The KV cache sits in the memory of the machine that runs the model. It grows with every token in the window, so a longer window needs more memory.

The KV cache is separate from the prompt cache, a provider feature that makes a repeated start of your prompt cheaper to process. The KV cache belongs to the model. The prompt cache belongs to the bill.

Bigger is not better

As the token count grows, accuracy and recall degrade. This is called context rot. Anthropic’s docs give no token count at which it starts, so check the source of any figure you see.

It compacts automatically as the limit nears: the history is replaced by a summary. The summary keeps your requests and key code snippets, but detailed instructions from early in the conversation may be lost.

Afterwards, Claude Code re-supplies:

  • the system prompt, the project-root CLAUDE.md, auto memory and skill descriptions
  • up to five recently read or edited files (a file over 5,000 tokens comes back as a path only)

Nested instruction files are summarised away and reload on demand.

Useful controls:

  • /context shows what is using space.
  • /compact with a focus note compacts on purpose.
  • /clear starts clean between unrelated tasks.

A subagent (a helper agent started by the main one) has its own window, and only a summary comes back. If one file or output is so big that the window refills after every summary, auto-compaction stops with an error.

Check OpenCode’s documentation for how it compacts and how it reports window usage. Expect any tool to drop or summarise something when the window is full. A local model may run with a smaller window, so check your model’s setting.

Hands-on: how big is a fresh session?

A fresh session is not empty: the items above load first, so every session has a starting size. Measure yours:

  • Claude Code
  • OpenCode + Ollama
  1. Start a new session (claude) and run /context before you type anything else. A /command is typed into the running session.
  2. Read the table by category. The starting load is the system prompt, system tools, MCP server instructions, memory files and skills. Messages is the conversation, and it should be close to zero.
  3. Look at the MCP and tool lines marked deferred. Their figures say how many tokens they would take if all were loaded. Only their names are in the window until a tool is needed.
  4. Note the largest starting item and whether you chose it. Fewer MCP servers, plugins and skills, or a shorter instructions file, lower it.
  5. Open a long session you already have and run /context there. The difference is the part a fresh start removes.
  1. Send one short message: opencode run -m ollama/qwen3:4b "Say hello in one sentence."
  2. While the model is loaded (Ollama keeps it for a few minutes), run ollama ps in a second terminal.
  3. Read two columns. CONTEXT is the window the server set aside, in tokens. SIZE is the memory the loaded model uses, and it includes the working memory for that window.
  4. A larger CONTEXT needs a larger SIZE. If your model spills onto the CPU, the PROCESSOR column says so.

An agent a session starts for you can start large. A subagent started from a brief begins with that brief. A forked agent (an option in some tools) inherits the whole conversation, so it starts as large as the session that spawned it. A new session or agent that opens with a high count is worth checking with /context before you work in it.

Three habits

  1. Start fresh for a new task. An unrelated earlier thread takes room and can distract.
  2. Keep outputs small. In bioinformatics terms: ask for the head, a count, or a summary script’s output when the file is a big variant table or a whole log.
  3. Put durable facts in the instructions file, such as how to run tests or which folders are off limits. Instructions given only in chat can be lost to compaction. Keep that file short: aim for under 200 lines, because longer files use more context and reduce how well the agent follows them.
