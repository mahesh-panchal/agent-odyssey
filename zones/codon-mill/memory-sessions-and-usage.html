Memory, Sessions and Usage

You walk back to the Codon Mill, where Miller Garrick keeps three ledgers: what an Astral remembers between visits, what it holds during one visit, and what the visit costs. The morning before, it greeted you as a stranger, then followed a rule from a stray note you had forgotten writing. A wrong entry in the first two ledgers is hard to erase. Garrick shows you how to read each one alone, so that when something goes wrong you know which to open.

  • Goal: you will use six terms precisely (token, context window, session context, memory, session usage, context poisoning), and say what to do when a wrong claim has got into a session or into memory.
  • Before you start: The Context Window. Commands here are Claude Code commands.
  • Time: about 15 minutes.

This lesson matters now because the next lessons on sessions and cost depend on these terms. People say “it remembers”, “the session got long” and “I hit my usage” as if these were one thing. They are different things, each stored in a different place and reset in a different way. Knowing which is which tells you what to clear when a wrong claim has got in, and why a long session costs more.

The glossary

  • Token: a chunk of text the model reads (a word piece, a character or a byte). Context limits and usage are counted in tokens.
  • Context window: everything the model can see when it writes its next output. It has a size limit, measured in tokens.
  • Session and session context: a session is a saved conversation tied to a project directory (stored locally as a transcript file). Its session context is what is in the window right now. Each session begins with a fresh context window, and sessions are independent: a new session has no history from earlier ones.
  • Memory: text on disk that is read into a new window at the start of every session.
  • Session usage: how much of your allowance a session consumes.
  • Context poisoning: a wrong or injected statement enters the context and later answers build on it. The term is community vocabulary. A commonly cited example is a game-playing agent whose recorded goals became corrupted with false state.

Memory in Claude Code

Both kinds are loaded at session start:

  • CLAUDE.md: instructions you write (the file can be set at project, user or organisation scope: who or where it applies).
  • Auto memory: notes the harness (the program around the model) writes itself from your corrections and preferences. It is per git repository and machine-local, kept in ~/.claude/projects/<project>/memory/ as plain markdown with a MEMORY.md index. Only the start of MEMORY.md loads at session start (the docs give the limit); topic files are read on demand.

Memory is advisory context, and it takes room in the window every session. /clear (a command that starts a new, empty conversation) drops the conversation and leaves memory in place. Compaction (replacing old conversation with a summary) shrinks a session and leaves memory as it was.

Session usage in Claude Code

  • /usage shows an estimated session cost (worked out locally from token counts at list price, the published per-token price), plan usage limits and activity stats.
  • The displayed session total resets on /clear. The allowance itself resets on your plan’s schedule: look for a reset time in the /usage screen. If your plan shows none, /usage is not reporting it.
  • With a subscription, the plan bars on the /usage screen are what matter and the dollar figure is an estimate. If the screen shows no bars, your plan reports no limits there.
  • With the API, usage is billed per token, and thinking tokens (the tokens the model spends reasoning before it answers) count as output tokens.
  • Allowance sizes are on the vendor’s pricing page.

Why usage climbs

  • Claude Code sends the whole conversation on every request, and each tool-using step is another request.
  • Caching (a short-term store so repeated text is cheaper to re-read) makes re-reading cheaper, but a short question late in a long session still draws on all of it.
  • Large tool outputs stay in the conversation. Reading a 10,000-line log is one example.
  • Subagents (helper agents with their own context window) each have their own context, and their requests still count.
  • /compact itself reads the whole conversation.
  • Cached text expires after a set time. If you leave the session idle for longer than that, the next message re-sends everything at full price.

Remedies:

  • /clear between unrelated tasks.
  • /compact with a focus note.
  • /context to see what fills the window.
  • Keep CLAUDE.md under 200 lines.

If /usage shows “rate limited until …”, Claude Code could not fetch your plan limits. You can keep working.

When a wrong claim gets in

If you have corrected the same thing twice and it is still wrong, run /clear and write one new prompt that folds in what you learned. A third correction mostly adds to a conversation that already holds two failed attempts for the model to re-read. /rewind (a command that rolls the conversation back to an earlier turn) can return to before the bad turn.

Memory persists, so a wrong line costs the most there. Check a claim against the source, such as the data, the program’s own --help or the paper, before it goes into CLAUDE.md or auto memory. If a bad line is already there, open /memory, read what has been written about your project, and delete it.

Commands:

  • /memory: lists memory files, toggles auto memory, opens the folder.
  • /clear: new empty conversation; the old one stays resumable.
  • /compact: replace the history with a summary.
  • /resume and claude --resume: pick an earlier session.
  • claude --continue: the most recent session in this directory.
  • /usage and /context: usage and window contents.

Resume restores messages, model and permission mode (what the agent may do without asking). Startup flags such as --mcp-config need to be passed again. Old transcripts are deleted after a set time by default (check your settings).

Check OpenCode’s documentation for its memory files, session commands and usage reporting. With a local Ollama model the window is still finite, so the ideas about session context and poisoned claims carry over. Check whether any vendor bills you per token.
