Know Your Tools

In the sages’ college, Sage Maelis lays the Summoning Scroll open across her desk. She names each piece of the pact in turn: the Astral you will summon, the binding circle that holds it, and a pile of fittings nobody has labelled. She has heard the boasters swear a good pact needs nothing more than a name. Start with the Astral alone, then watch the circle go down around it.

  • Goal: you will use the words this site relies on (model, harness, skill, MCP, hook, plugin, effort, eval and the context terms below) and say how they fit together.
  • Before you start: Script, Model, or LLM.
  • Time: about 15 minutes.

People mix these words up, and the mix-ups cause real mistakes, such as blaming “the model” for something a setting did. The pictures below start with one part and add one more each time.

1. The model

  • Model. The large language model (LLM) that reads and writes text (for example a Claude model, a Mistral model, or a local model through Ollama, a program that runs models on your own computer). Aliases such as sonnet move to newer versions over time, so use the full model name when a result must be reproducible.
  • Effort. A setting for how much the model reasons before it answers, from low to max in Claude Code (/effort, --effort; a /command is typed inside the running tool, a --flag when you start it). Low is faster and cheaper; high thinks longer and checks more. It steers how much the model reasons per step. max can show diminishing returns and overthink, so raise it only where you measure a gain.

2. The harness

  • Harness. The program around the model. The product you type into is the harness. It provides the tools, manages the context the model sees, runs the loop (gather context, act, check, repeat) and enforces permissions. Claude Code, OpenCode (an open-source harness) and Mistral Vibe (Mistral’s open-source terminal coding agent) are harnesses.
  • Tool. An action the model can request and the harness runs, such as reading a file or running a shell command. A tool call is one such request; tool output is what comes back.
  • Permissions. The harness’s rules for which tool calls it runs, asks about or refuses.
  • Agent. A model inside a harness that picks and runs tools in a loop toward a goal.

3. Extensions

  • Instructions file. A text file (CLAUDE.md in Claude Code, AGENTS.md in OpenCode where read) that the harness loads at session start. It advises and does not enforce.
  • Skill. A folder with a SKILL.md. Only its short description is preloaded; the body loads when it is used. It advises.
  • MCP (Model Context Protocol). An open standard for connecting the harness to outside tools and data, such as a database or a literature search. A server you connect can act on your behalf, so treat it like software you install.
  • Hook. Your own command, request or prompt that the harness runs automatically at a set point, such as before a tool call. A command hook that exits with code 2 before a tool runs stops that action whatever the model wants (an exit code is the number a script returns; 0 means success, and a hook uses 2 to mean block). A rule in an instructions file can only ask, so hooks are the stronger guard.
  • Plugin. A folder that bundles skills, hooks, MCP servers and more, installed as one unit. It can run code, so install only plugins you trust.

4. Evals

  • Eval. A repeatable test of agent behaviour: a prompt plus checks on the result. Comparing runs with and without something (a skill, a rule) shows what it contributed. A score of 100% both ways means the test cannot tell the difference, so make it harder.

5. One model, different harnesses

The same model can behave differently in each harness, because tools, permission rules and the loop differ. Naming differs between tools too. Check another tool’s docs for how its hooks, plugins and effort settings work.

Other words you will meet

These are not in the pictures.

  • Prompt. The text you send to the model.
  • Turn. One prompt from you plus the model’s reply.
  • Subagent. A helper agent with its own context window; only its summary comes back.
  • Sandbox. An operating-system layer that limits what commands can touch.
  • Hallucination. A plausible-looking statement that is false, such as an invented DOI (a paper’s permanent identifier).
  • Prompt injection. Text from a file, web page or tool that the model treats as an instruction.

Words about what the model can see

These get mixed up more than any others.

  • Token. The chunk of text a model actually reads and writes. Somewhere between a letter and a word. Limits and costs are counted in tokens.
  • Context window. Everything the model can see at once right now: instructions, files it has read, tool output and the conversation so far. It has a size limit, and a fuller window is not automatically a better one.
  • Session (session context). One running conversation, and the context window it has built up. A new session starts with an empty conversation. Two sessions do not share their context.
  • Memory. Notes that the harness loads at the start of every session, such as your instructions file and, in Claude Code, notes the harness writes itself. Memory outlives a session; session context does not.
  • Compaction. The harness replaces old conversation with a summary to free room.
  • Session usage. How much of your allowance or bill a session spends. It climbs with the size of the context, because the whole conversation is sent again with each request.
  • Context poisoning. A community term: a wrong statement gets into the context, and later answers build on it. Start a fresh session and keep unverified claims out of memory files.
Redraw the picture from memory for the tool you actually use: which model, which harness, which extensions are loaded right now?
