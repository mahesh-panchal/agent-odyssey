Park Ideas for Later

You walk back to the mill, and ideas keep arriving as you work beside your Astral: what about this, could we also try that. Each one you shout across the mill drops into the hopper, and the job you came for sinks under the pile. Miller Garrick points to a board by the door where anything that can wait is pinned for the next visit. Learn what to pin, and what a pinned note must say so that the next visit can act on it.

  • Goal: you will sort each new idea during a task into act now or park, and park it in a file or memory entry that a later session can act on.
  • Before you start: The Context Window. Commands here are Claude Code commands.
  • Time: about 15 minutes.

You will finish a task with its side ideas written down for later, and your session stays short. You need this now because a longer conversation uses more of your usage allowance on every turn, and the task loses room to the side tracks.

Real work does not arrive in a straight line. You start fixing a samplesheet parser and think: “should I switch the aligner? What if I tried a stricter QC threshold? I also want to explore that other idea.” Typed into one conversation, each of those adds side tracks to the context. Claude Code sends the whole conversation with every request, and token costs grow with the context. Ideas are welcome. Triage (sort) each one.

Terms used here

  • Context: everything the model can see when it writes its next reply.
  • Session: one saved conversation with the agent, tied to a project folder.
  • Subagent: a helper the main agent starts. It works in its own clean context (it knows what you tell it) and sends back a summary, so its reading stays out of your conversation.
  • /subtask: a background helper that starts with a copy of the conversation so far and sends back its result.
  • /btw: a side question. It sees the conversation so far, has no tools and leaves no trace in the history.
  • Conversation branch (/branch, which is separate from a git branch): a copy of the conversation from this point, so you can try something in the copy while the original stays as it was.
  • Instructions file (CLAUDE.md): a file you write that loads at the start of every session.
  • Auto memory: notes the harness (the agent program around the model, such as Claude Code) saves for later sessions. /memory lists them.

The triage

For each new thought, ask in this order. The key question is step 2: do you need the answer or the work during this session? If not, park it. If you do, steps 3 to 6 are the ways to get it.

  1. Does it block the current task? Do it now, in this session.
  2. Do you need the answer or the work in this session? If not, park it: write the idea down in a file or memory (next section) and carry on.
  3. You need it now: is it a quick question you do not need on record? Use /btw <question>. It sees the conversation so far, has no tool access (it cannot read files or run commands) and adds nothing to the history. An answer about a tool’s flags or defaults comes from the model’s memory, so verify it against --help or the docs.
  4. You need it now: is it exploration where you only need a summary? Two helpers fit. Ask in plain words for a subagent (“use a subagent to find where the aligner is configured”; the built-in Explore helper is a fast read-only searcher). It starts clean and knows only what you tell it. Use /subtask <task> instead when the helper needs the conversation so far. Both return a result here.
  5. You need it now: is it a competing approach you want to try for real? Commit your work, then use /branch [name] to copy the conversation. To return to the original later, run /resume and pick it from the list.
  6. You need it now: is it a different task entirely? Finish the current one and commit. Name this session with /rename <name> so /resume can list it later, then /clear to start fresh, or start a new named session with claude -n <name>.
New thought Where it goes Why
“The parser crashes on this sample ID” (it is the task) Do now It blocks you
“Maybe a stricter QC threshold would help” Park it You do not need the answer this session, and a line in a file costs almost nothing
“Which sample did we exclude earlier?” /btw One answer from the conversation, with no tools and no history
“Where is the aligner configured across the repo?” Explore subagent or /subtask Heavy reading stays out of your main context, and you get a summary
“Try the other aligner and compare” Commit, then /branch A real attempt that can fail, kept apart from the main history
“Redo the plots for the other project” (you want to start it now) Commit, then /rename and /clear, or a new named session Different task, different files, different context

What a parked note must say

A parked idea helps only if a later session, or you in a week, can act on it without the conversation that produced it. Write one line per idea with five parts:

  • The idea, starting with a verb.
  • Why it matters.
  • The trigger: when to pick it up.
  • A pointer: the file, function, run ID or data location it concerns.
  • What you already know: a result, or an option you ruled out.
# IDEAS.md  (date | idea | why | revisit when | pointer | already known)
2026-11-28 | Add a --dry-run flag to the parser | Check a samplesheet without writing output | after the parser fix is merged | parse_sheet.py, main() | none
2026-11-28 | Raise the QC threshold from Q20 to Q30 | Fewer false variants in low-depth samples | when the test cohort is ready | qc_filter.py, MIN_Q | Q30 drops 12% of reads in sample A
2026-11-28 | Plot per-sample coverage | Spot dropouts faster | before the next batch | results/coverage.tsv | none

Where to save it

Place Loaded when Use it for
A parking-lot file such as IDEAS.md When you ask the session to read it The full list. Keep it in the repository if the team should see it, in a gitignored file if it is personal, or use an issue tracker for anything that outlives the week.
Auto memory At the start of every later session (Claude Code loads the first 200 lines or 25KB of its index, the list of saved notes) A follow-up the next session should know without being asked
The instructions file At the start of every session One pointer line to the parking-lot file

Each of the last two costs context in every session, so keep what you save there short. Keep the list in IDEAS.md and put only a pointer in the instructions file: Parked ideas are in IDEAS.md. Read it when I ask. Pasting the whole list into CLAUDE.md would load it every time.

To save a follow-up to memory, say so: Remember that the Q30 threshold idea is parked in IDEAS.md until the test cohort is ready. Claude decides what is worth remembering and does not save everything you say, so run /memory afterwards and read what it wrote. If a line is wrong, edit or delete it there. To start the next session on the list, say Read IDEAS.md and pick the ideas whose trigger has arrived.

Worked example

You are fixing a samplesheet parser that rejects sample IDs containing a dot.

  • “Does the pipeline require the dot at all?” blocks the fix, so do it now.
  • “Would a stricter QC threshold help?” becomes a line in IDEAS.md, with a pointer to qc_filter.py.
  • “Which sample did we exclude earlier?” is a /btw. For “what does --min-qual default to?”, /btw can only guess from memory, so check --help.
  • “Where else do we split sample IDs on dots?” is wide reading where only the list matters: send an Explore subagent.
  • “Let’s try the other aligner and compare.” is a real experiment you want now: commit the fix, then /branch.
  • “I should also tidy the figures for the other project.” is a different task for after the parser is done: commit, then /rename, /clear and start a named session.

The main session ends with the parser fixed, a short history and three parked lines.

Commands: /btw, /subtask, /branch, /rename, /clear, /resume, /memory, claude -n <name>. Ask Claude to “remember that …” to save a follow-up to auto memory, or “add this to CLAUDE.md” to write the instructions file.

Check OpenCode’s documentation for its side-question and branch features. Its terminal page lists /new for a fresh session and /sessions to return to one. OpenCode loads AGENTS.md as its instructions file, so put the pointer line there. In any tool, local models included, keep a parking-lot file and commit before exploring.
