The Project Charter

Prerequisites: Write the Brief. Who Said What is advised. Objective: give the agent standing instructions for a project, and know where they end and enforcement begins. Time: about 15 minutes. Last verified (docs, not run): Claude Code v2.1.323 and OpenCode docs (they describe V2; installed version not checked) on 2026-11-13 (sources in research/forest-and-reef.md and research/doctor.md).

Typing the same background every session is wasteful. A project instructions file is read at the start so the agent already knows the project’s conventions.

  • Claude Code
  • OpenCode + Ollama

The file is CLAUDE.md. It can live in ~/.claude/CLAUDE.md (all your projects), ./CLAUDE.md or ./.claude/CLAUDE.md (the project, shared if committed), and ./CLAUDE.local.md (yours, not committed). Files in the working directory and above are loaded at launch, and ones in subdirectories are loaded when needed. /init drafts one from your project and /memory lists and edits them. @path imports another file, and the imported text still uses context.

The file is AGENTS.md in the project root (or ~/.config/opencode/AGENTS.md for all projects). /init creates or updates it. The instructions array in opencode.json adds more files. OpenCode also falls back to CLAUDE.md if there is no AGENTS.md.

What goes in, and the limit

Put in facts the agent cannot guess: how to run the tests, where data lives, naming conventions, “never edit raw/”. Keep it short (the Claude Code docs aim for under 200 lines per file) because very long instructions are followed less well.

Warning

Instructions are advice. Claude Code’s docs describe CLAUDE.md as context, and not as enforced configuration. A line saying “never delete files” cannot stop a delete. Enforcement comes from permission rules, hooks, or managed settings (organisation-set rules you cannot override): the carapace you built in the Crypt.

Instruction files go stale too: a rule written for an older model, a path that no longer exists, two files that disagree. The docs warn that when instructions contradict each other, Claude may pick one arbitrarily. In Claude Code (v2.1.283 or later), /doctor prompt-audit (/doctor is a bundled skill, a ready-made skill that ships inside the tool) checks your instruction files for outdated or conflicting content and writes a report with proposed edits. It changes nothing until you ask. It checks content only, so size and cost are out of scope. The audit is itself a model reading your files, so review its suggestions like any other output. Not checked: an OpenCode equivalent.

Write the file yourself first and read what /init produces critically. A generated file can contain wrong guesses about your project.

Write a short instructions file (about ten lines) for one of your real projects: how to run its tests, where data lives, and one thing the agent should leave alone.
