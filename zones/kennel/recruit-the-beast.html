Recruit the Beast

Prerequisites: a terminal (macOS, Linux, or WSL 2, the Windows Subsystem for Linux, on Windows), internet, and a Claude Team plan login or an Anthropic API key (API = programmatic access to the models, billed per token; a plan is a subscription with usage limits). Objective: install Claude Code, confirm it works, and start it somewhere safe in read-only style. Time: about 15 minutes. Nothing here edits your files.

Last verified (docs, not run): Claude Code v2.1.323 on 2026-11-13, against code.claude.com/docs (sources in research/kennel-and-crypt.md and research/doctor.md). Docs change quickly; if a command differs, trust the official page and tell the maintainers.

The Beast

Claude Code is strong. Strength is the reason to put it on a short lead before you let it do anything.

1. Install

On macOS (Apple Silicon), Linux, or inside a WSL 2 terminal, run the native installer:

curl -fsSL https://claude.ai/install.sh | bash

On Windows, install inside WSL 2 and use the Linux command there. Check the result:

claude --version     # prints a version number
claude doctor        # read-only diagnostics; changes nothing

If the shell says command not found, the launcher lives in ~/.local/bin/claude and that folder is not on your PATH.

2. Log in

Run claude and a browser opens. With a Team plan, log in with the account your admin invited you to. With an API key, export ANTHROPIC_API_KEY=... instead.

Warning

If you have both a subscription login and ANTHROPIC_API_KEY set, the key is used once you approve it, so usage goes to the API account rather than your plan. Run /status (a /command is typed inside the running tool) to see which one is active; unset ANTHROPIC_API_KEY if you did not mean it.

3. Start on a short lead

Make a throwaway folder and start in plan mode, which reads files and runs read-only commands but does not edit your source:

mkdir -p ~/odyssey-scratch && cd ~/odyssey-scratch
claude --permission-mode plan

Shift+Tab cycles default, acceptEdits and plan inside a session; the status bar shows the current mode.

Mode What it does
default asks the first time each tool is used
acceptEdits auto-accepts file edits and common file commands (mkdir, touch, mv, cp) in the working directory
plan reads and runs read-only commands; does not edit source files
bypassPermissions skips prompts. The docs say to use it only in containers or VMs (virtual machines, a computer simulated inside yours)

4. Check the setup

Two commands share the name doctor, and they differ.

  • claude doctor (in the shell) prints read-only diagnostics of your installation and settings without starting a session. The docs say to use it when claude will not start. It changes nothing.
  • /doctor (a slash command, a /command typed inside the running tool; alias /checkup) runs inside a session. The docs call it a bundled skill (a ready-made skill that ships inside the tool); that suggests it runs through the model and may use some of your usage (our inference, not stated in the docs). It reports first and changes something only after you confirm. The areas the docs list: installation health, extensions versus their context cost, instruction files, permissions, and a usage check.

Not checked: whether /doctor also covers keybindings, sandbox availability or MCP configuration validity (the docs do not list them), and whether it makes network calls.

Which command shows what

Command What it shows
/status version, model, account, connectivity, and which settings sources are active
/context (/context all expands it) context use by category, with optimisation suggestions and warnings
/usage session cost and plan limits
/memory your CLAUDE.md files and auto memory, editable
/mcp MCP servers (tool plug-ins) and their connection status
/permissions allow, ask and deny rules by scope
/hooks configured hooks, grouped by event
/skills the skills available; press t to sort by token count
/skill-doctor per-skill context cost and how often each is used (v2.1.252+)
/doctor setup checkup: report first, fixes only after you confirm
claude doctor read-only install and settings diagnostics from the shell
claude --debug debug logging; logs go to ~/.claude/debug/<session-id>.txt

OpenCode: its CLI docs list no doctor or status command. opencode debug paths prints where its files live. Not checked: its TUI slash commands.

Before you ask for help

The docs say a bug report should include your OS, the install command and the full error output; /feedback sends feedback from inside a session. If you are unsure which problem applies, /doctor or claude doctor helps narrow it down. General practice: read any output before pasting it into a bug report or chat, because it can contain paths and account details. The docs give no advice on this, so the check is ours.
