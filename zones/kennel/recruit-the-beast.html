Set Up Your Agent

You return to the Collegium, where the sages’ college smells of ink and hot brass. An academic unrolls the Summoning Scroll you were given at Gaia’s Rest and reads it aloud, turning each rune into a step: this is how a pact is made. Making it is the easy part, the academic says, and then lists the ways it goes wrong, which the boasters at the tavern left out. Follow the scroll in order, and keep the Astral on a short lead.

  • Diviner Ilsa
  • Artificer Bob
  • Archivist Elowen

Guildmaster Aris asks what the pact will cost each month, and who signs it off.

Diviner Ilsa asks which Astral can cite its sources, and writes down how to check them.

Artificer Bob reads every command on the scroll before running one.

Archivist Elowen asks where the Astral keeps its memory, and for how long.

  • Goal: you will install a coding agent, confirm it works, and start it in a throwaway folder with edits switched off. You choose one of two routes: Claude Code with a Claude plan or API key, or OpenCode with a model that runs on your own computer through Ollama.
  • Before you start: Save Point; the Prerequisites check and, if you want background first, Read First; a terminal (macOS, Linux, or on Windows either PowerShell or WSL 2, the Windows Subsystem for Linux). For Claude Code: internet, and a Claude Team plan login or an Anthropic API key (programmatic access to the models, billed per token; a plan is a subscription with usage limits). For OpenCode and Ollama: about 16 GB of memory and 5 GB of free disk, and no account.
  • Time: about 15 minutes. Nothing here edits your files.

An agent can read your files and run commands, so the first session is in a throwaway folder, in a mode where it plans and does not edit your files. Pick a route in each tab below. The tab you pick stays selected on the other lessons, so you can follow the same route through the course. Both routes teach the same habits.

1. Install

  • Claude Code
  • OpenCode + Ollama

On macOS, Linux, or inside a WSL 2 terminal, run the native installer:

curl -fsSL https://claude.ai/install.sh | bash

To read the script before it runs, use curl -fsSL https://claude.ai/install.sh | less first.

On Windows, either run the PowerShell installer from Anthropic’s setup page, or install inside WSL 2 and use the Linux command there. WSL 2 supports sandboxed command execution; native Windows does not. Check the result:

claude --version     # prints a version number
claude doctor        # read-only diagnostics; changes nothing

If the shell says command not found, the launcher lives in ~/.local/bin/claude and that folder is not on your PATH.

This route has two programs. Ollama downloads and runs models on your own computer, so prompts stay there. OpenCode is the open-source coding agent that talks to the model. Install Ollama first.

  • macOS: download Ollama from ollama.com/download, open the .dmg file and drag Ollama into Applications.
  • Linux, or WSL 2 on Windows: curl -fsSL https://ollama.com/install.sh | sh
  • Windows: use WSL 2 and the Linux command above.

Check it, then fetch a small model (about 2.5 GB). qwen3:4b is one example that Ollama lists with tool support (the model can ask the agent to run actions such as reading a file). Model names change quickly, so check the “tools” badge on the model’s page at ollama.com/library.

ollama --version     # prints a line such as: ollama version is 0.x.y
ollama pull qwen3:4b # shows a download progress bar and ends with: success

Now install OpenCode. On macOS, Linux or WSL 2:

curl -fsSL https://opencode.ai/v2/install | bash
opencode --version   # prints a version number

On Windows, use WSL 2 and the same commands. If opencode is not found, open a new terminal and try again. To read an install script before it runs, use curl -fsSL <url> | less first.

2. Log in or connect the model

  • Claude Code
  • OpenCode + Ollama

Run claude and a browser opens. When login finishes, the terminal shows Claude’s prompt box. Type /exit to leave, then continue with step 3. With a Team plan, log in with the account your admin invited you to. With an API key, export ANTHROPIC_API_KEY=... instead. Treat the key like a password: do not paste it into a file in a project, and note that a key typed into the shell can stay in your shell history.

Note

If you have both a subscription login and ANTHROPIC_API_KEY set, the key is used once you approve it, so usage goes to the API account. Run /status (a /command is typed inside the running tool) to see which login is active. Run unset ANTHROPIC_API_KEY if you did not mean to use the key.

OpenCode needs no login. It looks for Ollama at http://127.0.0.1:11434 and lists the models it finds. Check that yours appears:

opencode models     # includes a line such as ollama/qwen3:4b

Agents need a long context length (how much text the model can see at once, counted in tokens, which are chunks of text). Ollama’s default can be as low as 4k tokens, and agents need at least 64k. If you use the Ollama app (macOS, or Windows with the app), open its settings and set the context length slider to 64k. On Linux or WSL 2 there is no app, so start the server yourself like this and leave that terminal open. Run every later command in a second terminal. If ollama serve says the address is already in use, Ollama is already running as a service: stop it first, or set the variable for that service as Ollama’s FAQ describes.

OLLAMA_CONTEXT_LENGTH=64000 ollama serve

A bigger context needs more memory. Run ollama ps while a model is loaded to see its size and whether it fits.

3. Start with edits off

Make a throwaway folder first:

mkdir -p ~/odyssey-scratch && cd ~/odyssey-scratch
  • Claude Code
  • OpenCode + Ollama

Start in plan mode. It reads files, runs read-only commands and leaves your source untouched:

claude --permission-mode plan

At the prompt, type: List the files in this folder and say what you would do next. Change nothing. Claude answers in the same session, and the status bar shows plan mode. Leave with /exit. Keep this first session away from real or sensitive data.

A permission mode sets what the agent asks about before it acts. In plan mode it reads files and writes a plan but does not edit your source until you approve; it may ask before running commands that are not read-only; the status bar shows the current mode.

OpenCode’s version of this is the plan agent (an agent is a preset bundle of instructions and permissions). It explores and plans without editing your project files. Send it one message:

opencode run --agent plan -m ollama/qwen3:4b "List the files in this folder and say what you would do next. Change nothing."

opencode run sends one message, prints the reply and exits. The first run can take a minute while the model loads. If you ask the plan agent to create a file, it declines.

The plan agent stops file edits only. Its shell commands are still controlled by OpenCode’s permission policy, and the default policy allows them. In this first session, ask for reading and planning only.

To use the full interface afterwards, run opencode in the folder and type /models to pick your Ollama model.

4. What to expect

  • Claude Code
  • OpenCode + Ollama

A hosted model is capable, and it has limits you should know before you rely on it:

  • Everything it reads, and everything you type, is sent to the provider.
  • Use is billed per token on an API key, or counted against your plan’s limits.
  • It can still be wrong with confidence, so check what it hands back.

A local model keeps your prompts on your computer, and it is weaker than a hosted one:

  • It holds less in mind. Agents need a context length of at least 64k tokens, and Ollama’s default can be 4k.
  • Choose a model that Ollama lists with tool support. Without it, the agent cannot ask the model to read or edit files.
  • It makes more mistakes than a hosted model. Test it on a few questions whose answers you know before you trust it on new ones.
  • A bigger model needs far more memory. A 24B model has about eight times the parameters (the numbers a model learns in training) of a 3B one, so check ollama ps after loading it, and expect the machine to slow down if memory runs short.
  • Its web and tool calls can still reach the network, even when the model itself stays local.

5. Check the setup

  • Claude Code
  • OpenCode + Ollama

Two commands share the name doctor.

  • claude doctor runs in the shell. It prints read-only diagnostics of your installation and settings without starting a session, so use it when claude will not start.
  • /doctor (alias /checkup) runs inside a session as a bundled skill, a ready-made skill, a packaged set of instructions, that ships with Claude Code. It reports first and changes something only after you confirm. It looks at installation health, extensions and their context cost, instruction files, permissions and usage.

Which command shows what

You do not need to run these now. Come back to the table when something looks wrong.

Command What it shows
/status version, model, account, connectivity, and which settings sources are active
/context (/context all expands it) context use by category, with optimisation suggestions and warnings
/usage session cost and plan limits
/memory your CLAUDE.md files and auto memory, editable
/mcp MCP servers (tool plug-ins) and their connection status
/permissions allow, ask and deny rules by scope
/hooks configured hooks, grouped by event
/skills the skills available; press t to sort by token count
/skill-doctor per-skill context cost and how often each is used
/doctor setup checkup: report first, fixes only after you confirm
claude doctor read-only install and settings diagnostics from the shell
claude --debug debug logging; logs go to ~/.claude/debug/<session-id>.txt

Four commands cover most first problems:

Command What it shows
opencode --version the installed OpenCode version
opencode models the models OpenCode can use, including your Ollama models
opencode debug paths where OpenCode keeps its config, data, logs and database
ollama ps the models Ollama has loaded, their size, and whether they run on the GPU or the CPU

If a model does not appear in opencode models, check that Ollama is running (open the app, or run ollama serve on Linux) and that you pulled the model with ollama pull. ollama ps lists a model only while one is loaded.

Before you ask for help

A bug report includes your OS, the install command and the full error output. Read any output before you paste it into a bug report or chat, because it can contain paths and account details. With Claude Code, /feedback sends feedback from inside a session, and /doctor or claude doctor narrows down a problem. With OpenCode, include the output of opencode --version and opencode debug paths.
