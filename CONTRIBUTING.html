Contributing to Agent Odyssey

Run it

pixi install, then pixi run preview (live) or pixi run render. pixi run e2e drives the built site with real key presses (needs quarto install chrome-headless-shell once). pixi run shots writes screenshots for review.

Add a quest

  1. pixi run new-quest <zone> <slug> "Title" creates zones/<zone>/<slug>.qmd and .yml.
  2. Add it to zones.yml under its gate, with id <zone>-<slug>, page, story and done text.
  3. Write the test bank (see rules below), then pixi run render && pixi run e2e.

Rules for content

  • Facts: check tool facts against official docs. Say “Verified: ran …” only if you ran it; otherwise “Last verified (docs, not run): on ” or “General practice”. Record sources in research/.
  • Unchecked claims: label them “Not checked:” or “General practice”, never “Last verified (docs, not run)”. Short third-party text, such as the hooks-guide script, is allowed when attributed.
  • No real company or product used as a villain. The enemy is the Blight: unchecked plausible-but-false output.
  • Sceptic-friendly: never imply LLM use is mandatory. Mitigations over cheerleading.
  • Exercises run on a laptop with tiny mock data. No real or sensitive data, ever.
  • Tests: discriminating, one defensible right answer, every wrong answer carries a misconception, every question has explain. Do not make the correct option the longest or the only hedged one. Types: choice, order, sort, faulty-line, match.
  • Honour items (data-ao-honour) give bonus XP only and never gate progress.
  • Accessibility: all text is real HTML; colour is never the only signal; everything works with the keyboard.

Lore

Each quest ends with a Lore block after the Battle div (pixi run new-quest scaffolds it): optional further reading, a plain always-visible section (not collapsible: Quarto’s collapse callout is not keyboard-focusable without custom JS). - What belongs: docs, articles, papers or repos a player can open to read more about this quest’s ideas. - Only sourced URLs. Every link must appear in a research/*.md file (read by the team) or in research/lore-extra.md (supplied by the maintainer). Never invent or guess a URL; the lint checks this. - One-line why: each item is - [Title](https://url): Publisher, kind. Why read: one line. with kind one of docs, article, paper, repo. Use https only, no duplicate URL in a quest. - 2-8 items per quest. Keep to the best few. - Third-party text is not copied. Link and say in your own words why it is worth reading. - pixi run lore lints the blocks; the Lore library page (lore.qmd, generated, gitignored) is built from them on render. It runs with --require, so a quest without Lore fails the lint (it runs before e2e).

Review before merging

Run pixi run shots right before review, then check REVIEW.md for the checklist.
