## 1. Fresh session vs continue
- CONFIRMED: `/clear` between unrelated tasks. "It costs nothing, and it means the next task doesn't keep paying for the previous one's history." `/clear oauth-migration` labels the session you are leaving so you can return. C best-practices#keep-cost-and-context-down
- CONFIRMED: a session with three unrelated tasks "re-reads all three on every turn of the fourth". Best-practices table also says a focused context "gets you better answers" and costs less, even with a 1M window. C best-practices
- CONFIRMED: after writing a spec, "start a fresh session to build from it, so the build begins with a clean context and a written definition of done" (SPEC.md via the interview prompt). C best-practices (spec section)
- CONFIRMED: Claude Code "compacts automatically as you approach the limit, so a full context window doesn't end your session". Levers before it fires: `/compact <focus>` (example `/compact focus on the auth bug fix`, "before starting a long new task"), `/rewind` then Summarize from/up to here, `/autocompact <tokens>` (e.g. `/autocompact 500k`), `/clear`, delegate large reads to a subagent. C context-window#when-your-context-fills-up
- CONFIRMED: `/context [all]` is the live fullness check: colored grid, optimisation suggestions, capacity warnings; `all` expands the per-item breakdown and lists loaded Memory files. C commands
- CONFIRMED: idle compaction exists: with the one-hour cache, a session past about 200K tokens that sits idle "is compacted shortly before the cache expires, so after lunch you continue from a summary. If you don't need the history at all, a fresh session still costs less." Cache is about one hour on a subscription, five minutes on API key/cloud/credits. C best-practices (cost section), C context-window (links `idleCompaction` setting)
- CONFIRMED: resume restores messages, model, permission mode (terminal `--continue`/`--resume`), active `/goal`; not `--mcp-config`, `--plugin-dir`, `--add-dir`, `--settings`, `--fallback-model` (pass again). If compacted, the resumed session continues from the last summary. C sessions#what-a-resumed-session-restores
- CONFIRMED: "Resume this conversation?" dialog (Pro/Max/Ultra, long conversation after a long break or different model) estimates share of the 5-hour limit the saved conversation alone would use; choices Resume or Start a new conversation. "Choose by whether your next task still needs the saved conversation." C sessions#the-resume-this-conversation-dialog
- CONFIRMED: two terminals resuming the same session both write one transcript; messages can go missing. Use `--fork-session` on each. C sessions#branch-a-session
- UNCONFIRMED: a documented context-percentage status-line field or "context fullness" signal. The statusline page was not fetched (`/statusline` exists, C commands). Fetch C statusline before claiming one.
- UNCONFIRMED: the exact auto-compact threshold; docs defer to model-config "Default auto-compact thresholds" (not fetched).
- Rule of thumb for the site (inference from the above): continue when the next step needs the same files, decisions and failed attempts; clear when the task changed, or when the transcript is mostly dead ends.

## 2. Handling a stream of side ideas
- CONFIRMED subagents: "Use one when a side task would flood your main conversation with search results, logs, or file contents you won't reference again: the subagent does that work in its own context and returns only the summary." Built-in Explore = fast read-only agent for searching codebases. Each invocation is a new instance unless you ask Claude to resume it; Explore and Plan are one-shot and cannot be resumed. C sub-agents; C common-workflows#delegate-research-to-subagents
- CONFIRMED: `/btw <question>` asks a side question "without adding to the conversation history". Works while Claude is busy; sees the conversation so far; no tool access (cannot read files or run commands); single response; press `f` to fork it into a background subagent with full tools. Newest 20 side exchanges are replayed to later `/btw`. C interactive-mode#side-questions-with-btw; C commands
- CONFIRMED: `/branch [name]` copies the conversation, switches you into the copy, original stays and is reachable by `/resume`. CLI form: `claude --continue --fork-session`. In-flight background subagents/Bash keep running and report into the branch, not the original. C sessions#branch-a-session; C commands
- CONFIRMED: `/subtask <task>` spawns a forked background subagent that inherits the whole conversation and returns its result here; `/fork [prompt]` copies the conversation into a separate background session (own worktree before code edits, v2.1.221+); `/background [prompt]` (alias `/bg`) detaches the current session. C commands
- CONFIRMED: you can type while Claude works; messages queue. A mid-turn message has no checkpoint of its own ("No code restore"). C interactive-mode#queue-messages-while-claude-works; C checkpointing
- CONFIRMED plan mode: Claude reads and proposes, no edits until approved; `claude --permission-mode plan`, `Shift+Tab` until the bar shows plan mode, or `/plan [description]`. The plan Claude wrote is re-injected from disk after compaction. Accepting a plan gives the session a generated title. C common-workflows#plan-before-editing; C commands; C context-window
- CONFIRMED checkpoints: every prompt that starts a turn is a checkpoint; last 100 kept. `/rewind` (aliases `/checkpoint`, `/undo`) or `Esc` `Esc` on empty input. Options: restore code and conversation / conversation only / code only / Summarize from here / Summarize up to here. Summarize leaves files alone and the original messages stay in the transcript. Pitch: "Exploring alternatives". C checkpointing
- CONFIRMED limits: files changed only by Bash are not tracked; subagent edits mostly not restored; external and other-session edits not tracked; symlinks/hard links skipped; "Not a replacement for version control"; snapshots swept after about 30 days. C checkpointing#limitations. Bioinformatics note (inference): `sed -i` or a script rewriting a results table is a Bash change, so commit first.
- CONFIRMED worktrees: `claude --worktree <name>` or `-w <name>` creates `.claude/worktrees/<name>/` on branch `worktree-<name>`; second terminal, second name = isolated parallel session. Docs suggest adding `.claude/worktrees/` to `.gitignore`. Fresh checkout: gitignored files (`.env`) absent unless listed in `.worktreeinclude`; data directories need `worktree.symlinkDirectories` or a setup step. C worktrees; C best-practices
- CONFIRMED: worktrees share `.git`, project-scope plugins, "don't ask again" permission rules (saved to main checkout `.claude/settings.local.json`); auto memory is per repository, all worktrees share it; a gitignored `CLAUDE.local.md` exists only in the worktree where created. Exit: clean unnamed worktree auto-removed; named or dirty one prompts keep/remove. C worktrees; C memory
- CONFIRMED: worktrees isolate file edits only; subagents split work inside one session; cross-session messaging lets sessions in worktrees pass findings. C worktrees (intro)
- CONFIRMED naming: `claude -n <name>` at startup, `/rename <name>`, `Ctrl+R` in the picker. Without a name `/rename` auto-generates one. Resume by `claude --resume <name>` or `/resume <name>`; ambiguous name opens the picker pre-filtered. Unnamed sessions get a generated title (usable as a handle), but the default `dir-xx` label is not. C sessions#name-your-sessions
- CONFIRMED picker (`/resume` or `claude --resume`): `Space` preview, `Ctrl+R` rename, `/` search (a PR URL finds its session), `Ctrl+W` all worktrees, `Ctrl+A` all projects, `Ctrl+B` current git branch. `claude --from-pr <number>` filters to a PR's sessions. `-p`/SDK/`/loop` sessions are hidden from the picker and `--continue`. C sessions#use-the-session-picker
- CONFIRMED: `/recap` makes a one-line summary on demand (cap 400 characters); an automatic recap appears after 3+ minutes away (3+ turns in). Off via `/config`. C interactive-mode#session-recap
- CONFIRMED: `/clear` then `/resume` restores the old conversation; in the same process the rewind menu has a "previous session" entry. C commands; C checkpointing
- OpenCode: UNCONFIRMED for share, branch/fork. `opencode.ai/docs/share` returned 404 (page may live elsewhere). CONFIRMED on the TUI page: `/new` (alias `/clear`), `/sessions` (aliases `/resume`, `/continue`), `/compact` (alias `/summarize`), `/undo` and `/redo` (need a git repo), `/export` (to Markdown in your editor). CONFIRMED on config page: `compaction` keys `auto`, `keep.tokens`, `buffer`. O tui, O config. Note the TUI page itself documents only manual compaction.

## 3. Between-session continuity
- CONFIRMED: "Each Claude Code session begins with a fresh context window"; CLAUDE.md and auto memory carry knowledge. Memory is "context, not enforced configuration". C memory (detail in failure-modes.md)
- CONFIRMED: asking "remember that the API tests require a local Redis instance" saves to auto memory; "add this to CLAUDE.md" writes the instruction file. Claude "decides what's worth remembering"; it does not save every session. `/memory` opens, toggles, lists. C memory
- CONFIRMED: `CLAUDE.local.md` at the project root holds private per-project preferences, "add `CLAUDE.local.md` to your `.gitignore`". It loads after CLAUDE.md in the same directory. For sharing across worktrees, import a file from your home directory. Only official guidance found on keeping notes out of git. C memory#claude-local-md (section anchor unverified)
- CONFIRMED: rules that are task-specific and not needed every session belong in skills, not CLAUDE.md. C memory (note under rules)
- CONFIRMED: `SessionStart` hooks matching the `compact` source run after compaction and add output to context (a route to re-inject notes). C context-window#what-survives-compaction
- CONFIRMED (Anthropic long-running agents): "getting agents to make consistent progress across multiple context windows remains an open problem"; each new session "begins with no memory of what came before". A first "initializer agent" sets up `init.sh`, `claude-progress.txt` and an initial git commit. A: effective-harnesses-for-long-running-agents
- CONFIRMED: feature list `feature_list.json`, every feature starts failing; agents may edit "only by changing the status of a passes field". JSON chosen because "the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files". (Summariser noted one stray reference to `tests.json` in the article.) A: same
- CONFIRMED: coding agent works on one feature at a time, commits with descriptive messages and updates the progress file, "so bad changes can be reverted". A: same
- CONFIRMED startup routine each session: `pwd`; read git logs and progress file; pick the highest-priority unfinished feature; read `init.sh`; run a basic end-to-end test before new work. A: same
- CONFIRMED failure table: declares victory too early (fix: feature list); leaves bugs or undocumented progress (git plus progress notes); marks features done prematurely (self-verify before marking passing); wastes time working out how to run the app (`init.sh`). A: same
- CONFIRMED (Anthropic context engineering): "structured note-taking": the agent "regularly writes notes persisted to memory outside of the context window" (examples: Claude Code to-do list, a `NOTES.md`); also compaction, sub-agents returning about 1,000 to 2,000 token summaries; "context rot" as recall degrades with growth. A: effective-context-engineering-for-ai-agents
- CONFIRMED: no official Claude Code page found that prescribes a handoff-file template or a scratch-file location. Do not present one as official.
- INFERENCE, general practice (handoff note contents): goal in one line; current state (branch, last commit, what runs); decisions with reasons and rejected options; verified (command and result) versus assumed or not run; open problems and traps (e.g. a reference genome build, a sample that fails); exact next step; pointers to files, job IDs, work directories, not pasted logs. Keep it short enough that reading it costs less than rediscovery.
- INFERENCE: pair the note with a commit so state is recoverable: a progress file mirrors Anthropic's pattern, git history is the audit trail. Write the note before `/clear`, not after, because `/clear` drops the conversation.
- COMMUNITY (unsourced, flag as such): ad hoc `HANDOFF.md`/`PROGRESS.md`/`NOTES.md` files, or asking the agent to "summarise this session into a file" before ending. The `session-handoff` skill in this environment is a local tool, not an Anthropic doc.
- UNCONFIRMED: whether `/export` output suits a handoff. It is "plain text ... for a person to read" (C sessions#export-and-locate-session-data); transcripts are long, so a curated note is better (inference).

## 4. Parking ideas
- No official Anthropic or OpenCode guidance found on a "parking lot" file. Treat all below as INFERENCE / general practice, not documented features.
- A `TODO.md`/`IDEAS.md` (or GitHub issues) outside the agent's current task: one line per idea, with where it came from and why it might matter. Capture, do not act. Matches the pull to "follow the shiny idea" that bloats context.
- Mechanisms the docs do support for the same job: `/btw` for a question that needs no action (no history cost); `/subtask` or Explore subagent to investigate an idea while the main thread continues; `/branch` to try it without losing the main path; a worktree session to build it in isolation; a named session (`/rename`) to find it later.
- Where to keep it (inference): in the repo if the team should see it; a gitignored file or `CLAUDE.local.md`-style local file if personal; an issue tracker for anything that outlives the week. Official docs only confirm that `CLAUDE.local.md` should be gitignored.
- Caution (inference): a parking-lot file the agent reads every session costs context. Do not import it from CLAUDE.md; point to it only when needed.

## 5. Exact names (documented; never invent others)
- Slash commands (C commands): `/clear [name]` (aliases `/reset`, `/new`), `/compact [instructions]`, `/context [all]`, `/autocompact [auto|<tokens>]`, `/resume [session]` (alias `/continue`), `/branch [name]`, `/fork [prompt]`, `/subtask <task>`, `/background [prompt]` (alias `/bg`), `/btw [question]`, `/rename [name]`, `/rewind` (aliases `/checkpoint`, `/undo`), `/recap`, `/export [filename]`, `/memory`, `/plan [description]`, `/statusline`, `/add-dir <path>`, `/cd <path>`, `/goal [condition|clear]`, `/usage`, `/config`, `/doctor`.
- CLI flags/commands: `claude --continue`, `claude --resume [name|id|path]`, `claude --continue --fork-session`, `claude --from-pr <n>`, `claude -n <name>`, `claude --worktree <name>` / `-w`, `claude --permission-mode plan`, `claude agents`, `claude attach <id>`, `claude stop <id>`, `claude purge`. C sessions, C worktrees, C commands
- Keys: `Esc` `Esc` (rewind menu on empty prompt), `Shift+Tab` (cycle to plan mode), picker `Ctrl+R/W/A/B`.
- NOT FOUND in docs: `/handoff`, `/park`, `/save`, `/notes`, `/fresh`. `/new` is only an alias of `/clear`. There is no documented `/summarize` in Claude Code (that is an OpenCode alias of `/compact`).
- Settings/env named: `cleanupPeriodDays` (30 days default), `worktree.baseRef` (`"fresh"`/`"head"`), `worktree.symlinkDirectories`, `.worktreeinclude`, `CLAUDE_CODE_DISABLE_TERMINAL_TITLE`.
