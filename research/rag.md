# RAG, its variants, alternatives, and graph RAG with Ollama

Sources read 2026-11-20 by three subagents, then checked against our own runs. Reading method: arXiv abstract pages and most web pages were read through a summarising fetch tool, so quotes are tool-reported and should be re-checked before being used verbatim. Four papers (2407.16833, 2307.03172, 2309.15217, 2412.15605) were converted from PDF to text and read in full. GitHub READMEs, docs and release data were read raw with `gh api`. Labels: (a) the source states it, (b) the authors report it about their own method, (c) our inference.

Used by `zones/codon-mill/rag-and-its-cousins.qmd` and `zones/codon-mill/grow-a-graph-with-ollama.qmd`.

## 1. Simple RAG and its improvements
- https://arxiv.org/abs/2005.11401 : Lewis et al., "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks", NeurIPS 2020 (v1 2020-05-22, v4 2021-04-12). Abstract only. (a) A generator ("parametric memory") paired with a dense vector index of Wikipedia read by a neural retriever ("non-parametric memory"); provenance and updating knowledge are called open problems. The common "chunk, embed, search, paste the top k into the prompt" recipe is a later simplification; no single primary source defines it.
- https://www.anthropic.com/news/contextual-retrieval : Anthropic, "Introducing Contextual Retrieval", 2024-09-19. Vendor post. (a) Prepending chunk-specific context before embedding and before BM25; "if your knowledge base is smaller than 200,000 tokens (about 500 pages)" put it all in the prompt, no RAG needed. (b) Top-20 retrieval failure 5.7% baseline; 35% fewer with contextual embeddings, 49% with BM25 added, 67% with a reranker (1.9%). Their stated limits: their own test domains, one embedding model, one reranker; too many chunks can distract the model; run your own evals. Prompt caching "reduces latency by more than 2x and costs by up to 90%" (as quoted there).
- https://arxiv.org/abs/2212.10496 : Gao et al., HyDE, 2022-12-20. Abstract only. (a) An LLM writes a hypothetical answer document, which is embedded to find real documents; the abstract admits it "is unreal and may contain false details".
- https://arxiv.org/abs/2305.14283 : Ma et al., "Query Rewriting for Retrieval-Augmented Large Language Models", v3 2023-10-23. Abstract only. (a) A rewriting step before retrieval.
- NOT CONFIRMED: no primary source was opened for BM25 hybrid search or cross-encoder rerankers as stand-alone techniques; only the Anthropic post above.
- https://arxiv.org/abs/2104.08663 : Thakur et al., BEIR, 2021. Abstract only. (b) BM25 is a "robust baseline" across 18 datasets.

## 2. Graph and other variants
- https://arxiv.org/abs/2404.16130 : Edge et al. (Microsoft), "From Local to Global: A Graph RAG Approach to Query-Focused Summarization", v2 2025-02-19. Abstract plus about 100k characters of the v2 HTML (https://arxiv.org/html/2404.16130v2). (a) Index: 600-token chunks, an LLM extracts entities, relationships and claims, hierarchical Leiden communities, bottom-up community summaries. Global queries map-reduce over community summaries. (a) Indexing a roughly 1M-token corpus took 281 minutes with gpt-4-turbo. (b) An LLM judge preferred it to vector RAG for comprehensiveness (72 to 83%) and diversity on 125 generated "global sensemaking" questions per dataset. (a) Limits: two corpora of about 1M tokens; fabrication not measured.
- https://microsoft.github.io/graphrag/ and https://microsoft.github.io/graphrag/index/overview/ : GraphRAG docs. (a) TextUnits, entity and relationship extraction, Leiden clustering, community summaries; global search for holistic questions, local search that fans out from entities.
- https://microsoft.github.io/graphrag/get_started/ : (a) `python -m pip install graphrag`, `graphrag init`, `graphrag index`, `graphrag query "..." --method local`; `init` creates `input/`, `.env`, `settings.yaml`. Warning quoted: "GraphRAG can consume a lot of LLM resources!"; start with the small tutorial dataset and cheaper models. Release v3.3.0 on 2026-10-08 (`gh api`).
- https://microsoft.github.io/graphrag/config/models/ : (a) Uses LiteLLM; the model "must support returning structured outputs adhering to a JSON schema"; "built and tested using OpenAI models"; for Ollama and similar proxies, "we frequently see issues with malformed responses (especially JSON)". NOT CONFIRMED: any documented Ollama provider setup (docs list none).
- https://arxiv.org/abs/2410.05779 : Guo et al., "LightRAG: Simple and Fast Retrieval-Augmented Generation", v3 2025-04-28. Abstract plus v3 HTML (https://arxiv.org/html/2410.05779v3). (a) An LLM extracts low-level (entity) and high-level (theme) keywords from the query; a vector index matches them to entities and relations; one-hop neighbours are added. New documents are merged into the graph, no full rebuild. (b) Win rates by LLM judge (GPT-4o-mini, 125 generated questions per dataset) against NaiveRAG 60.0 to 84.8%, against GraphRAG 49.6 to 54.8%. (b) A cost comparison on the Legal dataset only.
- https://github.com/HKUDS/LightRAG : README and docs (`docs/ProgramingWithCore.md`, `docs/LightRAG-API-Server.md`) read raw. Release v1.5.8rc1 on 2026-11-15. (a) Query modes local, global, hybrid, naive, mix (default). (a) "higher capability requirements for LLMs than traditional RAG"; non-thinking model strongly recommended; README: "Qwen3-30B-A3B-Instruct is a reasonable minimum" for local extraction; `ProgramingWithCore.md`: "at least 32B parameters, 32KB context (64KB recommended)" (the two differ; neither cites a benchmark). Models under about 50 tokens/second may time out. Default storage is in-memory JSON, NanoVectorDB and NetworkX, for testing only. The embedding model must be chosen before indexing and kept.
- https://arxiv.org/abs/2401.18059 : RAPTOR, Sarthi et al., 2024. Abstract only. (a) Recursively clusters and summarises chunks into a tree. (b) +20% absolute on QuALITY with GPT-4.
- https://arxiv.org/abs/2405.14831 : HippoRAG, Jimenez Gutierrez et al., NeurIPS 2024. Abstract only. (a) LLM, knowledge graph and Personalized PageRank. (b) Up to 20% better multi-hop QA.
- https://arxiv.org/abs/2310.11511 : Self-RAG, Asai et al., 2023. Abstract only. (a) A fine-tuned model that decides when to retrieve and critiques passages with reflection tokens. (c) Needs a trained model.
- https://arxiv.org/abs/2401.15884 : Corrective RAG, Yan et al., 2024. Abstract only. (a) A retrieval evaluator that triggers different actions, with a web-search fallback.
- https://arxiv.org/abs/2501.09136 : Singh et al., "Agentic Retrieval-Augmented Generation: A Survey on Agentic RAG", v4 2026-04-01. Abstract only. A survey; no new head-to-head evidence.
- NOT CONFIRMED: no source read for multimodal RAG.

## 3. Independent evaluations
- https://arxiv.org/abs/2502.11371 : Han et al., "RAG vs. GraphRAG: A Systematic Evaluation and Key Insights", v4 2026-11-07, read via the HTML (https://arxiv.org/html/2502.11371v4); tables partly cut off, spot-check before quoting. (a) "complementary behaviors rather than a consistent winner". Single-hop NQ F1: RAG 64.78, Community-GraphRAG (Local) 63.01, a triplets-only method 34.28. Multi-hop HotpotQA F1: HippoRAG2 63.01 against RAG 60.04. Construction time on MultiHop-RAG: RAG 135 s against 5,560 s for Community-GraphRAG. Only about 65% of answer entities appear in the built graph. LLM-judge results flip with presentation order (one example 0.97 to 0.03 flipping to 0.12 to 0.88). Running both and combining gave +6.4% on one benchmark with a 70B model.
- https://arxiv.org/abs/2506.05690 : Xiang et al., "When to use Graphs in RAG", v3 2026-02-22 (HTML https://arxiv.org/html/2506.05690v3, first 100k of 182k characters). (a) Graphs help when a task connects concepts across documents and may add noise on simple fact lookups. Average prompt tokens per query: RAG 879, MS-GraphRAG local 38,707, LightRAG 100,832 (the paper's own text contradicts some figures; verify before quoting). Do not quote the "13.4% lower on NQ" figure it cites; it was not verified.
- https://arxiv.org/abs/2506.02404 : Xiao et al., a different "GraphRAG-Bench" (1,018 college-level computer science questions), v3 2025-06-20. (a) Accuracy: no retrieval 70.68, BM25 71.66, best graph methods 72.5 to 73.6; some graph methods fall below no retrieval. Only GPT-4o-mini tested.

## 4. Alternatives to RAG
- https://arxiv.org/abs/2407.16833 : Li et al., "Retrieval Augmented Generation or Long-Context LLMs? A Comprehensive Study and Hybrid Approach", EMNLP 2024 industry. Full text. (b) "when resourced sufficiently, LC consistently outperforms RAG" (average +7.6% Gemini-1.5-Pro, +13.1% GPT-4O, +3.6% GPT-3.5-Turbo); RAG is much cheaper; the two give the same answer for over 60% of queries. Their Self-Route (RAG first, fall back to long context) cut cost 39 to 65%. RAG failure kinds they list: multi-step, general or summary queries, implicit queries, long or ambiguous queries. Limit: three 2024 models.
- https://arxiv.org/abs/2307.03172 : Liu et al., "Lost in the Middle", TACL. Full text. (a) Accuracy is higher when the relevant passage is first or last in the context; GPT-3.5-Turbo multi-document QA drops by more than 20% in the middle; reader performance "saturates long before retriever recall". 2023 models.
- https://arxiv.org/abs/2412.15605 : Chan et al., "Don't Do RAG: When Cache-Augmented Generation is All You Need for Knowledge Tasks", WWW '25 Companion. Full text. (b) Preload all documents and precompute the KV cache; Llama 3.1 8B on SQuAD and HotPotQA; says it "becomes impractical for significantly larger datasets". Small Wikipedia-style benchmarks.
- https://platform.claude.com/docs/en/build-with-claude/prompt-caching : Anthropic prompt caching docs, first 100k of 166k characters, via summariser. (a) Resume from cached prefixes; cache reads priced below normal input; default 5-minute lifetime; minimum cacheable length depends on the model; hits need identical prefixes; output is unchanged. Prices change by model, so none are quoted on the site.
- https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents : Anthropic Engineering, 2025-09-29, via summariser. (a) Agents keep lightweight identifiers and load data "just in time"; "primitives like glob and grep allow it to navigate its environment and retrieve files just-in-time" in Claude Code; hybrid with some up-front retrieval; "runtime exploration is slower than retrieving pre-computed data". No benchmark.
- https://www.anthropic.com/engineering/writing-tools-for-agents : Anthropic Engineering, 2025-09-11, via summariser. (a) Prefer targeted search tools to list-everything tools; pagination and truncation; Claude Code caps tool responses at 25,000 tokens by default.
- https://code.claude.com/docs/en/how-claude-code-works : Claude Code docs, full text. (a) Lists a Search tool category. It does NOT say why there is no embedding index. SECONDARY ONLY, not used on the site: reports of a Claude Code lead explaining that early versions used a vector database and that agentic search worked better (Pragmatic Engineer newsletter summary); the X post was not opened.
- https://modelcontextprotocol.io/docs/getting-started/intro : MCP intro, via summariser. (a) An open standard for connecting AI applications to external systems, including databases. NOT CONFIRMED: no opened primary source says why embedding search is poor for exact filters and counts. That point on the site is labelled General practice.
- https://developers.openai.com/api/docs/guides/optimizing-llm-accuracy : OpenAI, "Optimizing LLM Accuracy", via summariser. (a) Optimise context when the model lacks knowledge or it is out of date; optimise the model when output is inconsistent; fine-tune only if the problem is consistency or behaviour and not context; the guide's Icelandic example says RAG "confounded the model by giving it extra noise".
- https://arxiv.org/abs/2312.05934 : Ovadia et al., "Fine-Tuning or Retrieval? Comparing Knowledge Injection in LLMs", 2023. Abstract only. (b) Unsupervised fine-tuning gives modest gains; RAG performs better overall.
- https://arxiv.org/abs/2405.05904 : Gekhman et al., "Does Fine-Tuning LLMs on New Knowledge Encourage Hallucinations?", EMNLP 2024. Abstract only. (b) New facts are learned slowly and, once learned, raise hallucination. Neither paper tests LoRA; applying them to LoRA is our inference.

## 5. Risks and evaluation
- https://arxiv.org/abs/2302.12173 : Greshake et al., indirect prompt injection, 2023. Abstract only. (a) "LLM-Integrated Applications blur the line between data and instructions"; instructions planted in retrievable content; mitigations "currently lacking" as of 2023.
- https://genai.owasp.org/llmrisk/llm01-prompt-injection/ : OWASP LLM01:2025, via summariser. (a) Indirect injection arrives through external sources such as websites or files; RAG and fine-tuning "do not fully mitigate" it; mitigations include least privilege, human approval for risky actions, marking untrusted content, filtering, adversarial testing.
- https://privacy.claude.com/en/articles/7996866 : Anthropic privacy centre, page dated 2026-07-01, via summariser. (a) API inputs and outputs deleted within 30 days with listed exceptions. Whether commercial inputs are used for training is NOT CONFIRMED from this page; see `privacy-and-unpublished-work.md`.
- https://arxiv.org/abs/2309.15217 : Es et al., "Ragas", v2 2025-04-28. Full text. (a) Reference-free metrics: faithfulness (claims supported by the retrieved context), answer relevance, context relevance. (b) Agreement with human preference on a small Wikipedia set: 0.95, 0.78, 0.70. An LLM does the judging. It does not measure retrieval recall, which needs labelled relevant passages. Splitting retrieval from generation is our inference.

## 6. Ollama and the tools
- https://docs.ollama.com/capabilities/embeddings : Ollama docs, via summariser. (a) `POST /api/embed` with `model` and `input` (string or list); response field `embeddings`, one vector per input; vectors are L2-normalised; use the same embedding model for indexing and querying. Our run of `/api/embed` with `nomic-embed-text` matched this.
- https://ollama.com/library/nomic-embed-text : (a) 274 MB, 2K context window; dimensions not listed. LightRAG's docs use 768 for it.
- https://ollama.com/library/embeddinggemma and https://ollama.com/library/qwen3-embedding : (a) embeddinggemma 622 MB, 2K context, needs Ollama v0.11.10 or later; qwen3-embedding 0.6b is 639 MB with 32K context.
- https://docs.ollama.com/capabilities/structured-outputs : (a) Pass a JSON schema in `format`; set temperature to 0 for more deterministic output; "Ollama's cloud currently does not support structured outputs". Our run used this with `gemma4:12b-mlx`.
- https://docs.ollama.com/context-length : (a) Defaults by video memory: under 24 GiB 4k, 24 to 48 GiB 32k, 48 GiB or more 256k; `OLLAMA_CONTEXT_LENGTH=64000 ollama serve`; check with `ollama ps`. It does not mention `num_ctx`; our scripts pass `num_ctx` per request in `options`.
- https://github.com/gusye1234/nano-graphrag : README read raw. Latest release v0.0.8 (2024-10-01), last push 2026-01-27, effectively dormant. An example uses Ollama; its own comment says a 7B model "may produce unparsable results". Not taught.
- https://github.com/neo4j/neo4j-graphrag-python : README and docs source read raw. Release 1.24.0 (2026-11-10); `OllamaLLM` class; needs a Neo4j database.
- https://developers.llamaindex.ai/python/framework/module_guides/indexing/lpg_index_guide/ : LlamaIndex property graph guide, via summariser. (a) `PropertyGraphIndex`, extractors, in-memory default store. Ollama wiring NOT CONFIRMED from this page.
- https://github.com/kuzudb/kuzu : repository archived ("We are archiving the KuzuDB project"). Not taught.
- Issue-only evidence, not official: https://github.com/microsoft/graphrag/issues/2231 (default vector size 3072 clashes with smaller non-OpenAI embedding models).
- NOT CONFIRMED: any official indexing-time estimate for local small models.

## 7. Our own runs (2026-11-20, macOS, Ollama 0.40.16)
Chat model `gemma4:12b-mlx`, embedding model `nomic-embed-text`, in `exercises/codon-mill/mini-rag` with twelve short mock notes (233 words). One run each at temperature 0; not repeated.
- Heron question (multi-hop): simple RAG k=3 retrieved the Pipeline 2.4, Pipeline 2.3 and Project Heron notes, missed the run log, and answered "The notes do not contain the answer." k=5 added the run log and answered correctly. `--all` (every note in the prompt) answered correctly. The graph walk answered correctly.
- `graph.py build`: 67 facts in 1 minute 20 seconds. Sample flaws kept as teaching material: `You --bring--> own cup` from the lunch note, and a stray leading space in a name (now stripped when loading).
- The graph walk starting from three entities and two hops collected 40 of the 67 facts, from 8 of 12 notes.
- Corpus-wide question ("Who works in this group, and what does each person do?"): k=3, `--all` and the graph walk all answered that the notes do not contain the answer. The notes never list a roster, so the question may simply be a poor one.
- Not run: LightRAG, Microsoft GraphRAG, any other model, `qwen3:4b`.
